# النظام المالي والإداري للمدرسة

نظام ويب (لوحة تحكم) عربي بالكامل من اليمين لليسار لإدارة الشؤون المالية لمدرسة خاصة: الطلاب وذممهم وأقساطهم وخصوماتهم، سندات القبض والصرف، الموظفون والرواتب، الموردون والمقاولون، الصناديق والبنوك، التقارير، الاستيراد من Excel، المستخدمون والصلاحيات، سجل النشاط، النسخ الاحتياطي، والمحاسبة العامة الكاملة.

الواجهة بسيطة لغير المحاسبين («ذمة، دفعة، سند قبض، سند صرف»)، وفي الخلفية محرك قيد مزدوج: كل مستند يُنشئ قيدًا متوازنًا في نفس معاملة قاعدة البيانات، فتبقى الدفاتر والقوائم المالية مطابقة للشاشات دائمًا.

> وثائق التصميم الكاملة (البنية، قاعدة البيانات، الصفحات، الصلاحيات، سير العمليات، الحالات الاستثنائية، سجل النشاط، النسخ الاحتياطي، الترقيم، الاستيراد، العلاقات المحاسبية) في مجلد [`docs/`](docs/README.md).

## أبرز الإمكانيات

| المجال | ما يوفره النظام |
|--------|-----------------|
| الطلاب والعائلات | ملف الطالب، ولي الأمر والإخوة، التسجيل السنوي، تغيير الحالة، ترحيل الطلاب للسنة الجديدة |
| الذمم والأقساط | ذمة فردية أو جماعية، تقسيط تلقائي أو جدول مخصص، خصومات (مبلغ/نسبة)، إعادة جدولة، رسوم مقررة لكل صف |
| القبض | دفع سريع يوزّع على أقدم المستحقات، دفعة عائلية، رصيد دائن، شيكات، مرتجع، طباعة سند رسمي مع التفقيط |
| الصرف والخزينة | سندات صرف بأنواعها، موردون وفواتيرهم، عمال ومقاولون، صناديق وبنوك وتحويلات، كشوف حساب |
| الرواتب | موظفون ومعلمات، ساعات إضافية، سلف بأقساط، مسير شهري (احتساب ← اعتماد ← صرف)، قسيمة راتب |
| التقارير | 23 تقريرًا مطلوبًا + ميزان المراجعة والميزانية، فلترة شاملة، تصدير Excel وCSV وPDF وطباعة |
| الاستيراد | 10 أنواع من Excel/CSV بقوالب جاهزة، ربط تلقائي للأعمدة، معاينة وتحقق، واستيراد «الكل أو لا شيء» |
| الإدارة | مستخدمون وأدوار وصلاحيات دقيقة (إضافة/حجب لكل مستخدم)، شركاء ونسب ملكية، سجل نشاط غير قابل للتعديل |
| السنوات | إغلاق السنة بقيد إقفال وتوزيع الأرباح على الشركاء، إعادة الفتح بقيد عكسي |
| المحاسبة العامة | دليل الحسابات، القيود اليومية واليدوية، الأستاذ، ميزان المراجعة، قائمة الدخل، الميزانية، فحص سلامة البيانات |
| الحماية | كلمات مرور مشفرة (scrypt)، جلسات آمنة، قفل الحساب بعد المحاولات الفاشلة، CSP، حماية CSRF، نسخ احتياطية مشفرة AES-256-GCM |

## التقنيات

Next.js 16 (App Router) · React 19 · TypeScript · PostgreSQL 16 · Prisma 7 · Tailwind CSS 4 · ExcelJS · Chromium (لملفات PDF) · Vitest

## التشغيل السريع باستخدام Docker (موصى به للإنتاج)

```bash
cp .env.example .env
# عدّل في .env على الأقل: POSTGRES_PASSWORD و ADMIN_PASSWORD و BACKUP_ENCRYPTION_KEY
docker compose up -d --build
```

- تعمل ثلاث خدمات: قاعدة البيانات، ثم خدمة `migrate` (تطبّق ترحيلات القاعدة والبيانات الأساسية ثم تتوقف)، ثم التطبيق على المنفذ `3000`.
- المرفقات والنسخ الاحتياطية في مجلد التخزين `/data/storage` (وحدة التخزين `storage`)، وقاعدة البيانات في `pgdata`.
- صورة التطبيق تحتوي أدوات PostgreSQL 16 (للنسخ والاستعادة) وChromium (لتوليد PDF على الخادم).
- عند التحديث: `git pull && docker compose up -d --build` (تُطبّق الترحيلات الجديدة تلقائيًا).
- ضع النظام خلف HTTPS (مثل Nginx أو Caddy) عند النشر على الإنترنت؛ ملفات تعريف الارتباط تصبح آمنة تلقائيًا مع HTTPS.

## التثبيت بأمر واحد على خادم (حتى لو كان يشغّل تطبيقات أخرى)

السكربت `deploy/server.sh` يفحص الخادم ويثبّت النظام معزولًا تمامًا. يستخدم مشروع Docker وقاعدة بيانات خاصين به، ويعمل على `127.0.0.1` مع حدود للموارد. يضيف ملف موقع مستقلًا في nginx أو Apache مع شهادة HTTPS، ولا يلمس أي تطبيق آخر. التفاصيل في [`deploy/README.md`](deploy/README.md).

```bash
curl -fsSL -o school.sh https://raw.githubusercontent.com/Baraaa-Nihad/Accounting-System/claude/accounting-system-web-l8z9mu/deploy/server.sh
sudo bash school.sh check   --domain school.example.com
sudo bash school.sh install --domain school.example.com
```

## التشغيل بدون Docker (تطوير أو خادم مباشر)

المتطلبات: Node.js 22، PostgreSQL 16 مع أدوات `pg_dump` و`pg_restore`، و(اختياريًا) Chromium لملفات PDF.

```bash
npm ci
cp .env.example .env          # اضبط DATABASE_URL و BACKUP_ENCRYPTION_KEY
npx prisma migrate deploy      # إنشاء الجداول والتريجرات
npx prisma db seed             # الأدوار، دليل الحسابات، الصفوف، الصندوق الرئيسي، المستخدم المدير
npm run dev                    # بيئة التطوير على http://localhost:3000
# أو للإنتاج:
npm run build && npm run start
```

## أول دخول

- اسم المستخدم: قيمة `ADMIN_USERNAME` (الافتراضي `admin`)، وكلمة المرور: قيمة `ADMIN_PASSWORD`.
- يُطلب تغيير كلمة المرور عند أول دخول.
- ابدأ من **الإعدادات**: بيانات المدرسة والشعار، العملة والمنطقة الزمنية، السنة الدراسية الحالية، الصفوف والشعب، تصنيفات الذمم، ثم أضف المستخدمين من **المستخدمون والصلاحيات**.
- للانتقال من نظام سابق استخدم **استيراد Excel** بالترتيب المقترح في الصفحة (الطلاب ← الموظفون ← الأرصدة ← الذمم/الأقساط ← السندات).

## متغيرات البيئة

| المتغير | إلزامي | الوصف |
|---------|:------:|-------|
| `DATABASE_URL` | ✅ | رابط قاعدة PostgreSQL |
| `BACKUP_ENCRYPTION_KEY` | ✅ | مفتاح تشفير النسخ الاحتياطية (16 حرفًا على الأقل). **احفظ نسخة منه خارج الخادم؛ بدونه لا يمكن فتح أي نسخة** |
| `STORAGE_DIR` | | مجلد المرفقات والنسخ الاحتياطية (الافتراضي `./storage`) |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | | المستخدم المدير الذي يُنشأ عند أول تهيئة فقط |
| `CHROMIUM_PATH` | | مسار Chromium لتوليد PDF (بدونه تبقى الطباعة و«حفظ كـ PDF» من المتصفح متاحة) |
| `APP_INTERNAL_URL` | | الرابط الداخلي الذي يفتح منه Chromium صفحات الطباعة لتوليد PDF (مضبوط في Docker على `http://127.0.0.1:3000`؛ الافتراضي رابط الطلب نفسه) |
| `COOKIE_SECURE` | | `true` أو `false` لفرض/تعطيل ملفات تعريف الارتباط الآمنة (الافتراضي حسب HTTPS) |
| `PG_BIN_DIR` | | مجلد `pg_dump`/`pg_restore` إن لم يكونا في `PATH` |
| `BACKUP_CRON_TOKEN` | | رمز تشغيل النسخ من cron خارجي عبر `npm run backup` |
| `DISABLE_BACKUP_SCHEDULER` | | `true` لتعطيل مجدول النسخ الداخلي |
| `TEST_DATABASE_URL` | | قاعدة منفصلة للاختبارات فقط |

## النسخ الاحتياطي والاستعادة

- كل نسخة **ملف واحد مشفّر** (AES-256-GCM) يضم قاعدة البيانات كاملة (مع سجل النشاط) والمرفقات والشعار.
- **تلقائيًا** يوميًا في الوقت المحدد في الإعدادات (افتراضيًا 02:00 بتوقيت المدرسة) مع الاحتفاظ بآخر 14 نسخة، و**يدويًا** من «الإعدادات ← النسخ الاحتياطي».
- من نفس الصفحة: تنزيل النسخة لحفظها خارج الخادم، رفع نسخة خارجية، التحقق من سلامة أي نسخة، والاستعادة (تتطلب كلمة المرور وعبارة تأكيد، وتؤخذ نسخة أمان تلقائيًا قبلها).
- تنبيه في لوحة التحكم إذا مرّ أكثر من يومين دون نسخة.
- بديل للمجدول الداخلي: `BACKUP_CRON_TOKEN=... APP_URL=http://localhost:3000 npm run backup` من cron.

## الاختبارات

- `npm test` يشغّل اختبارات الوحدة والتكامل على قاعدة اختبار حقيقية (تُهيأ بالترحيلات تلقائيًا دون حذف أي شيء): المبالغ والتقريب، التفقيط، القيود لكل عملية مالية، الإلغاء بالقيود العكسية، الترقيم تحت التزامن، الرواتب، التقارير، الاستيراد (بما فيه «الكل أو لا شيء» ومنع التنفيذ المزدوج)، الصلاحيات، المحاسبة العامة، إغلاق السنة والترحيل، النسخ الاحتياطي والاستعادة، وفحوص سلامة البيانات.
- سكربتات المتصفح في `scripts/e2e-*.mjs` تختبر دورات العمل كاملة من الواجهة (تتطلب خادم تطوير يعمل و Chromium).

```
  server/
    services/       منطق الأعمال لكل وحدة (كل عملية مالية داخل معاملة واحدة)
    ledger/         المحرك المحاسبي: الترحيل، العكس، الأرصدة، الكشوف
    reports/        محرك التقارير وتعريفات التقارير

docs/               وثائق التصميم
```

## الأمان باختصار

- كلمات المرور بـ scrypt مع salt لكل مستخدم، وقفل الحساب بعد محاولات فاشلة متكررة، وتسجيل كل محاولة دخول.
- جلسات عشوائية تُخزن مجزّأة (SHA-256) مع انتهاء بعد عدم النشاط، وإنهاء الجلسات عند تغيير كلمة المرور أو التعطيل.
- التحقق من الصلاحية على الخادم في كل صفحة وعملية، وتسجيل محاولات الوصول المرفوضة.
- استعلامات مُعلمة فقط (منع SQL Injection)، سياسة أمان محتوى صارمة مع nonce (منع XSS)، وحماية CSRF.
- لا حذف للحركات المالية: الإلغاء بقيد عكسي مع السبب ومن ألغى ومتى، وتريجرات في القاعدة تمنع تعديل القيود وسجل النشاط.
