# 9. آلية سجل النشاط (Audit Log)

## 9.1 الهدف

معرفة **من فعل ماذا ومتى وما الذي تغيّر** لكل عملية في النظام، بحيث لا يمكن لأي مستخدم تعديل مبلغ أو إلغاء سند أو تغيير صلاحية دون أن يبقى أثر دائم.

## 9.2 ما يُسجّل في كل سطر

| الحقل | المحتوى |
|-------|---------|
| `userId` / `userName` | المستخدم (مع نسخة من اسمه وقت العملية حتى لو تغيّر لاحقًا) |
| `action` | نوع العملية: `create`، `update`، `cancel`، `delete`، `login`، `logout`، `login_failed`، `approve`، `pay`، `export`، `import`، `backup`، `restore`، `permissions`، `close_year`، `promote`... |
| `entityType` / `entityId` / `entityLabel` | الكيان المتأثر (مثل: `Receipt` / 152 / «سند قبض REC-2026-000152») |
| `summary` | وصف عربي مقروء: «إلغاء سند قبض REC-2026-000152 بقيمة 500.00 — السبب: شيك مرتجع» |
| `before` | **البيانات قبل التعديل** (JSON) |
| `after` | **البيانات بعد التعديل** (JSON) |
| `ip` / `userAgent` | عنوان الجهاز والمتصفح |
| `createdAt` | **التاريخ والوقت** بدقة |

## 9.3 كيف يُكتب

- كل خدمة تستدعي `audit.log(tx, {...})` **داخل نفس المعاملة** التي تنفذ العملية. إذا فشلت العملية لا يُكتب السجل، وإذا فشل السجل تفشل العملية؛ لا توجد عملية بدون سجل.
- الحقول الحساسة (مثل `passwordHash`) تُحذف تلقائيًا من `before`/`after`.
- المبالغ تُحفظ كنصوص دقيقة داخل JSON (`"500.000"`) لمنع فقدان الدقة.

## 9.4 العمليات الحساسة (تُميّز في العارض)

تغيير مبلغ، إلغاء سند قبض أو صرف، إضافة/إلغاء خصم، تغيير راتب موظف، تعديل ذمة طالب أو إلغاؤها، إعادة جدولة أقساط، تغيير صلاحيات أو دور مستخدم، فك قفل حساب، إغلاق/إعادة فتح سنة، استعادة نسخة احتياطية، القيود اليدوية، تعديل الإعدادات، استيراد البيانات.

## 9.5 منع التلاعب بالسجل

1. لا توجد في النظام أي شاشة أو دالة لتعديل أو حذف سجل النشاط.
2. **تريجر في قاعدة البيانات** يرفض أي `UPDATE` أو `DELETE` على جدول `audit_logs` حتى لو حاول أحد التعديل مباشرة عبر SQL (إلا بصلاحيات مدير القاعدة وتعطيل التريجر صراحة، وهو ما يظهر في سجلات القاعدة).
3. السجل مشمول في كل نسخة احتياطية.

## 9.6 محاولات الدخول

جدول مستقل `login_attempts` يسجل كل محاولة: اسم المستخدم المُدخل، النجاح/الفشل وسببه (كلمة مرور خاطئة، حساب مقفل، حساب معطل، مستخدم غير موجود)، IP، المتصفح، الوقت. يُستخدم لقفل الحسابات ولرصد محاولات الاختراق.

## 9.7 العرض

صفحة «سجل النشاط»:
- فلترة حسب: المستخدم، نوع العملية، نوع الكيان، الفترة، نص البحث (رقم سند مثلًا).
- عرض كل سطر: الوقت، المستخدم، العملية، الكيان، الوصف.
- نافذة التفاصيل: **جدول مقارنة** للحقول التي تغيرت (القيمة قبل ← القيمة بعد) بألوان واضحة.
- من داخل أي سند أو طالب: تبويب/زر «سجل التعديلات» يعرض سجل هذا الكيان فقط.
