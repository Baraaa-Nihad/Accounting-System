# تشغيل النظام على خادم فيه تطبيقات أخرى

السكربت [`server.sh`](server.sh) يثبّت النظام على أي خادم Linux عبر Docker، **معزولًا تمامًا** عمّا يعمل على الخادم من مواقع وتطبيقات. يناسب تشغيل النظام مؤقتًا على خادم تطبيق آخر ريثما يُجهَّز خادم خاص، ويُستخدم بنفس الأوامر على الخادم الخاص لاحقًا.

## ما الذي يفعله السكربت، وما الذي لا يلمسه

| يُنشئ للنظام فقط | لا يلمس أبدًا |
|------------------|---------------|
| مجلد `/opt/school-accounting` (الكود والإعدادات) | أي حاوية Docker أخرى: لا إيقاف ولا إعادة تشغيل |
| مشروع Docker باسم `school-accounting` بحاوياته وشبكته ووحدات تخزينه | قواعد بيانات التطبيقات الأخرى |
| قاعدة PostgreSQL خاصة بالنظام، **غير منشورة على أي منفذ** | ملفات إعدادات المواقع الأخرى |
| التطبيق على `127.0.0.1` فقط، مع حدود للذاكرة والمعالج وتدوير للسجلات | الجدار الناري |
| ملف موقع مستقل في nginx أو Apache (يُفحص بـ `nginx -t` أو `apache2ctl -t` قبل التفعيل، ويُحذف فورًا إن رُفض) | الصور وذاكرة البناء المشتركة في Docker |
| شهادة HTTPS مجانية لنطاق النظام فقط، تتجدد تلقائيًا | |

- إعادة تحميل خادم الويب «هادئة» (graceful): لا تنقطع الاتصالات الجارية للمواقع الأخرى.
- لا يبدأ التثبيت إلا بعد عرض الخطة وتأكيدك، ويرفض البناء إذا كانت الذاكرة المتاحة أقل من 1.5 GB حتى لا يضغط على التطبيقات الأخرى.
- هذا السلوك مُختبَر آليًا على خادم Ubuntu حقيقي يشغّل موقعًا وحاويات أخرى، خلف nginx وApache وCaddy وبمنفذ مباشر. يتحقق الاختبار أن الموقع الآخر وحاوياته وإعدادات خادم الويب بقيت كما هي بعد التثبيت والتحديث والإزالة ([`server-install.yml`](../.github/workflows/server-install.yml)).

## التثبيت

1. **نطاق فرعي للنظام** (مثل `school.example.com`): أضف في إعدادات DNS سجل `A` يشير إلى IP الخادم. في Cloudflare اجعله «DNS only» (السحابة الرمادية).
2. ادخل إلى الخادم عبر SSH ونفّذ:

```bash
curl -fsSL -o school.sh https://raw.githubusercontent.com/Baraaa-Nihad/Accounting-System/claude/accounting-system-web-l8z9mu/deploy/server.sh

sudo bash school.sh check   --domain school.example.com   # فحص فقط: يعرض الخادم والخطة ولا يغيّر شيئًا
sudo bash school.sh install --domain school.example.com   # التثبيت (يعرض الخطة ويطلب التأكيد)
```

3. في النهاية يطبع السكربت **الرابط واسم المستخدم وكلمة مرور مؤقتة** (يطلب النظام تغييرها عند أول دخول) و**مفتاح تشفير النسخ الاحتياطية**. احفظ المفتاح خارج الخادم.

البناء الأول يستغرق بضع دقائق. بدون نطاق يمكن التشغيل على منفذ مباشر، لكن الاتصال يكون غير مشفّر، فاستخدمه للتجربة فقط:

```bash
sudo bash school.sh install --port 8090      # http://IP-الخادم:8090
```

### المتطلبات

- خادم Linux (يفضّل Ubuntu أو Debian) وصلاحية `root`.
- Docker مع Compose v2. إن لم يكن مثبتًا أضف `--install-docker` ليثبّته السكربت من المصدر الرسمي.
- أثناء البناء فقط: ذاكرة متاحة (RAM + swap) لا تقل عن 1.5 GB. بعد التشغيل يستهلك النظام عادة 300–500 MB.
- مساحة قرص حرة لا تقل عن 6 GB.

### خادم الويب (يُكتشف تلقائيًا)

| الموجود على الخادم | ما يفعله السكربت |
|--------------------|------------------|
| nginx | ملف موقع مستقل للنطاق + شهادة HTTPS |
| Apache (بنمط Debian/Ubuntu) | موقع مستقل للنطاق + تفعيل وحدات `proxy` و`headers` إن لزم + شهادة HTTPS |
| لا شيء على المنفذين 80 و443 | خادم Caddy داخل مشروع النظام مع HTTPS تلقائي |
| غير ذلك (لوحة تحكم، Traefik، …) | يشغّل النظام على `127.0.0.1:PORT` ويطبع إعدادات الربط لتضيفها في لوحتك |

يمكن فرض الاختيار بـ `--web nginx|apache|caddy|none`.

## الإدارة

```bash
S=/opt/school-accounting/app/deploy/server.sh
sudo bash $S status      # الحاويات وهل النظام يستجيب
sudo bash $S update      # تنزيل آخر إصدار وإعادة البناء والتشغيل (البيانات تبقى)
sudo bash $S logs        # سجلات التطبيق (أو: logs db)
sudo bash $S info        # الرابط وبيانات أول دخول ومفتاح النسخ
sudo bash $S https       # استخراج الشهادة لاحقًا (إذا لم يكن DNS جاهزًا وقت التثبيت)
sudo bash $S uninstall   # إزالة النظام بالكامل دون المساس بغيره
```

الإعدادات السرية (كلمة مرور القاعدة، كلمة مرور أول دخول، مفتاح النسخ) في `/opt/school-accounting/config.env`، ولا يقرؤها إلا `root`.

## النقل إلى الخادم الخاص لاحقًا

1. من النظام الحالي: **الإعدادات ← النسخ الاحتياطي ← نسخة يدوية**، ثم **تنزيل**.
2. على الخادم الجديد، ثبّت بنفس المفتاح حتى يستطيع فتح النسخة:

   ```bash
   sudo bash school.sh install --domain school.example.com --backup-key 'مفتاح-النسخ-من-الخادم-القديم'
   ```

   المفتاح يظهر في الخادم القديم بالأمر `info`.
3. من النظام الجديد: **الإعدادات ← النسخ الاحتياطي ← رفع نسخة** ثم **استعادة**.
4. غيّر سجل DNS ليشير إلى الخادم الجديد إن استخدمت نفس النطاق، ثم أزل النسخة المؤقتة من الخادم القديم:

   ```bash
   sudo bash /opt/school-accounting/app/deploy/server.sh uninstall
   ```

إن أردت البدء على الخادم الجديد ببيانات جديدة فتجاهل الخطوات 1 و3 وخيار `--backup-key`.

## حل المشكلات

| المشكلة | الحل |
|---------|------|
| فشل استخراج الشهادة | تأكد أن سجل `A` يشير إلى الخادم (وفي Cloudflare: «DNS only») ثم نفّذ `https`. النظام يبقى متاحًا عبر HTTP حتى ذلك الحين |
| «Only … MB of memory is free» | أضف ذاكرة swap أو أوقف ما لا يلزم، أو أعد المحاولة وقت الهدوء مع `--force` |
| المنفذ 80/443 تستخدمه لوحة تحكم أو حاوية | اتبع إعدادات الربط التي يطبعها السكربت في لوحتك |
| النظام لا يستجيب | `status` ثم `logs`، وأرسل الناتج للدعم |
